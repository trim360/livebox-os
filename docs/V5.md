# V5 Rebirth / Guide d’utilisation

## English

V5 preserves the V4 router APIs and persistent data. Use the existing [installation guide](INSTALL.md) and Docker Compose configuration. No Docker socket is mounted, no cloud account is required and the default bind address remains loopback. The interface is currently French.

The home dashboard supports reordering by drag or keyboard buttons, three widget sizes and visibility controls. Quick settings provide per-account theme, blue/cyan/violet accent, performance/balanced/ultra motion, session restoration and JSON workspace export/import. Existing avatar and wallpaper features remain available. Ctrl+K focuses application/device search. A focused window title supports arrow keys, Shift+arrows for resizing and Enter for maximizing. On phones applications use full-screen views above the dock.

Register Linux hosts in **Serveurs**, generate a dedicated SSH key, install its public key on the intended non-root account, and independently compare the presented host fingerprint before trusting it. The backend never requests your personal SSH private key. **Informations système** reads CPU, RAM, storage, network counters, uptime, processes, services and journals with that account's permissions. Resource collection runs while a connected Livebox OS session exists; history keeps up to seven days / 20,000 samples. Unavailable metrics stay unavailable. Network counters are totals, not invented throughput rates.

**Docker** and **Terminal SSH** require explicit per-server permissions. Docker access can be equivalent to control of the host; use a deliberately provisioned account. V5 does not add groups or use sudo. Starting, stopping or restarting a container requires its name to be typed, an expiring session-bound confirmation and a final state read. Containers belonging to this deployment cannot be stopped through this interface. Images, volumes and containers cannot be deleted. Inspect results exclude environment variables and command arguments. Logs may contain application data and are restricted to operators/administrators.

The terminal uses the same verified SSH identity. It has bounded scrollback, resize, explicit reconnect and a one-hour session limit. Closing the window closes the connection; commands are not replayed or logged by Livebox OS. Remote shell history is controlled by the remote account. Browser clipboard permissions and shortcuts vary.

**Explorateur Linux** lists at most 500 entries in explicitly allowed directories. Canonical paths and symlink targets must remain inside the allowed root; `/` is refused. This is a read-only directory browser, not a remote file editor.

**Service Monitor** performs bounded HTTP HEAD checks against explicitly configured private destinations, without redirects, credentials, query tokens or response bodies. HTTPS certificate verification remains enabled. A 2xx/3xx response is available; 4xx/5xx is an HTTP error; timeout/network/TLS failure is inaccessible. Unknown means no measurement yet. Checks continue without an open browser; state transitions appear in Notifications. CPU/RAM/disk thresholds are configured in Automatisations and notify on crossings and recovery, not every sample.

The original administrator can create up to 16 viewer/operator accounts and suspend their access. All permissions are enforced by the backend. Viewers can connect read sessions and personalize their profile/workspace; operators can additionally read logs and confirm Docker actions. SSH terminal, registry changes, account management and service configuration require the administrator. Router credentials remain session-only; after backend restart they must be entered again. Workspaces and avatars are isolated per account; the legacy wallpaper/profile backup remains installation-wide and requires the administrator for changes.

The existing Backup app exports/imports router profiles, legacy appearance and wallpaper with confirmation. It does not back up SSH credentials or the entire server. Workspace JSON export covers V5 layout settings only. Use a private Docker volume backup for full disaster recovery; never commit it to Git.

## Français

- **Accueil** : personnalisez, déplacez, redimensionnez ou masquez les widgets. Les réglages rapides enregistrent le thème et l’espace de chaque compte. Les fenêtres peuvent être restaurées à la connexion.
- **Serveurs** : ajoutez le compte SSH non-root, installez la clé publique dédiée et vérifiez l’empreinte par un canal indépendant. Connectez le profil pour la collecte historique.
- **Docker / Terminal / Explorateur Linux** : activez uniquement les permissions souhaitées pour ce serveur. Les commandes Docker nécessitent une confirmation. Les dossiers doivent être autorisés explicitement. Aucun sudo, socket Docker public ni privilège automatique.
- **Service Monitor** : configurez les URL privées à vérifier. Les contrôles continuent côté serveur et les changements d’état produisent des notifications.
- **Automatisations** : configurez les seuils CPU, RAM ou stockage et les événements réseau. Une mesure manquante ne devient jamais un zéro.
- **Comptes** : lecteurs, opérateurs, suspension d’accès, avatar et espace personnels. Les mots de passe des routeurs restent en mémoire de session et doivent être ressaisis après un redémarrage.

## Boundaries / Limites

Livebox 5 and Archer AX58 are the previously verified hardware. Photos for other identified models do not imply protocol compatibility. Router auto-reconnection cannot recover credentials deliberately discarded after session expiry. Linux features depend on `/proc`, systemd, journal permissions, Docker CLI / Compose and readable thermal sensors. HTTP HEAD may be unsupported by some services. Docker historical CPU/RAM charts are not collected; the statistics view shows actual current reads. There is no process killing, file editing, destructive Docker cleanup, English UI translation or Nimbo integration. Window transitions respect reduced motion; no universal frame-rate guarantee is made.

## API and persistence

`/api/workspace` validates and atomically stores bounded per-account JSON. `/api/accounts` manages secondary local accounts. `/api/servers/{id}` provides permission policy, allowlisted reads, scoped SFTP listing, confirmed container actions and the authenticated same-origin terminal WebSocket. `/api/services` configures explicit HTTP checks. Existing `/api/control/history/{id}` includes CPU/RAM/disk samples. All HTTP writes require the existing session and CSRF token; server-side roles are checked before dispatch. Managed SSH keys, accounts, policies, workspaces and service configuration live only in the private data volume. New SQLite tables are additive.
